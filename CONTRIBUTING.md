# Contributing Guidelines

## Branching Strategy

The project uses `main` as the stable integration branch.

Feature and maintenance branches should follow these naming conventions:

- `feat/<feature-name>` — New functionality
- `fix/<issue-name>` — Bug fixes
- `docs/<documentation-name>` — Documentation changes
- `refactor/<change-name>` — Code restructuring without changing behavior

Examples:

```text
feat/frontend-fidelity
feat/api-integration
feat/system-integration
fix/responsive-layout
docs/project-documentation
```
